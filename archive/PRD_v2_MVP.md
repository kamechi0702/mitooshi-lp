## 1. ワンライナー

> 軽度ASD/ADHDの子どもと保護者が、**いつものシーンをカードで事前に作っておき**、外出先や日常で**ワンタップで取り出して、子どもが自分でカードをめくりながら**「次の行動」を見通せるようになるアプリ。

---

## 2. Why — なぜ作るか

軽度ASD/ADHDの子どもは「次に何が起きるか」が分からないと切り替えに失敗する。一方、目で見て自分で操作できれば自走できる力を持っている。既存ツールは「準備が面倒」「機能過多／不足」「外出時に持ち出せない」「子どもが飽きる」のどこかで詰まっている。

mitooshi v2は「**事前に組んでおいたシーンが、ワンタップで取り出せる**」「**子どもが自分でカードをめくる**」「**イラストで行動内容が視覚的に伝わる**」の3点で、軽度層の生活ど真ん中の負担を引き取りに行く。タイマーや実行中編集など機能の重さは意図的に削り、**「カードをめくる」一点に体験を集中させる**。

---

## 3. 成功の定義

### North Star Metric
**1ユーザーあたりの週次シーン実行完了回数**
（事前登録したシーンが、日常で繰り返し取り出されている状態を最も忠実に測る）

### Phase 1 検証KPI（v2向けに見直し）

| KPI | 目標値（暫定） | 観測理由 |
|---|---|---|
| D7継続率 | ≥ 35% | 「日常で手放せない」化の最低ライン |
| 初回シーン登録完了率 | ≥ 60% | オンボーディング後にマイシーンを1つ以上作れたか |
| シーン実行→完了率 | ≥ 75% | 子どもがカードを最後までめくれているか（タイマーがない分、純粋な体験品質指標） |
| 1ユーザーあたり週次実行回数 | ≥ 5回 | 朝・夜・外出など複数シーンで使われているか |
| ストア評価 | ≥ 4.3 | 療育文脈での信頼形成 |
| 有料転換率 | ≥ 5% | フリーミアム成立性 |

### 検証で「失敗」と見なすシグナル
- D7継続率 < 20%
- シーン登録完了率 < 40%（カード作成画面の体験設計に問題）
- レビューで「カードが足りない」が頻出（カードライブラリの網羅性不足）

## 5. プロダクト原則（MVP判断基準）

機能・UI・コピー判断は常に以下に照らす。**反する施策は機能価値があっても却下する**。

1. **2タップで取り出せる** — TOPからシーン実行までを最大2タップ。「いま使う」までの摩擦をゼロに近づける
2. **カードめくりに集中する** — タイマー・通知・編集など「めくる」以外の体験要素は意図的に削る
3. **子どもが主役** — 子ども自身がスワイプしてカードを進める。親が代行しない
4. **見て分かる** — 文字よりイラスト。アニメ調の行動イラストが体験の核。絵文字には頼らない
5. **2画面分離** — 親の作成・管理画面と、子どもが触る実行画面を明確に分ける

## 6. MVPスコープ（IN / OUT）

### IN（v1で必ず作る）
- TOP画面：マイシーン一覧（事前登録したシーンが並ぶ）
- 初回起動時のオンボーディング：プリセット人気シーン3つ＋「もっとつくる」を表示
- カード作成画面：場面別カテゴリから既製カードを探して並べる
- カード確認画面（実行）：**縦型積層レイアウト**で現在カード＋次カードが見え、子どもが**上スワイプ**でめくる、イラスト中心、絵文字なし
- カード完了演出：軽量な「できた！」表示＋次カードのせり上がりアニメーション
- シーン完了演出：その場限りの達成アニメーション（スタンプ・蓄積系UIは含まない）
- AI画像生成によるカードイラスト一括制作（本番アセット）


- ローカル永続化（オフラインで完結）
- フリーミアム課金の枠組み

### OUT（v1では作らない）
- **タイマー機能**（残り時間表示・カウントダウン）
- **実行中の予定変更／カード追加・削除**
- **じぶんでカードをつくる（カスタムカード作成）**
- **スタンプ蓄積コレクション機能**
- AI自動生成（自然言語→シーン自動構築）
- 家族共有・端末間同期
- 達成履歴・週次レポート
- 通知・リマインダー
- 子どもプロフィール（複数児童切り替え）
- toB事業所向け
- 音声読み上げ・キャラクターボイス
- タブレット最適化レイアウト

### 意図的に保留（要検証）
- 既存シーンの並べ替え・削除（v1で必要な編集導線。最低限残す方向）
- シーン名の編集（v1で必要だが優先度は中）
- カードの再生成リクエスト（特定カードを別バージョンに差し替えるニーズが出るか）

## 7. コアユーザーフロー（5本）

### F1: 初回起動からシーン実行まで
オンボーディング（簡易・3画面以内）→ TOP（プリセット3シーン＋もっとつくる） → プリセットの「あさのしたく」をタップ → カード確認画面 → 子どもがスワイプ → シーン完了（スタンプ演出） → TOPに戻る

### F2: いつものルーティン（朝の支度）
TOP → 「あさのしたく」タップ → カード確認画面 → 子どもがスワイプで進める → 完了

### F3: 新しいシーンを事前に作る（夜にゆっくり）
TOP → 「もっとつくる」 → カテゴリ選択（「びょういん」） → 既製カードリスト表示 → 必要なカードをタップで追加 → 順番調整（▲▼） → シーン名入力 → 保存 → TOPに新シーンが並ぶ

### F4: 外出先で使う（事前登録済み）
TOP → 「びょういん」タップ → カード確認 → 子どもがスワイプ → 完了

### F5: 外出中に終わらせたい（緊急ストップ）
カード確認画面 → 親が長押しで「やめる」を選択 → TOPに戻る（v1では実行中の組み換えはやらない／単純ストップ）

## 8. 機能要件（FR）

### FR-001 TOP画面（マイシーン一覧）
- ユーザーが登録したシーンをカードグリッドで表示（縦スクロール、2カラム）
- 各シーンカード：シーンサムネイル（代表カードのイラスト）、シーン名、カード枚数
- タップで即実行（カード確認画面に直行）
- 「＋ もっとつくる」ボタンを常時表示（最後のスロット or 固定位置）
- 長押しで編集モード（並べ替え・削除）— v1.0最低ラインで実装
- 初回起動時はプリセット人気シーン3つ＋「もっとつくる」が並んでいる
- 無料プランの上限（例：シーン3枚まで）は表示で示し、超過時に課金導線

### FR-002 オンボーディング（最小）
- 初回起動時に2〜3画面：「mitooshiは何のアプリか」「カードをめくる体験」「もっとつくる導線」
- スキップ可能
- 個人情報入力なし（メアド任意、子どもの名前は任意）
- 完了後、プリセット3シーンが入った状態のTOPに着地

### FR-003 カード作成画面（シーン作成・編集）
- ステップ1：カテゴリ選択（場面別タブ：「あさ」「よる」「おでかけ」「びょういん」「がっこう」「たべる」など）
- ステップ2：選択カテゴリ内の既製カード一覧をグリッド表示
- カードタップ→「えらんだカード」セクションに追加
- 「えらんだカード」セクションでは▲▼で順番調整、×で削除
- 上部にシーン名入力欄（例：「あさのしたく」）
- 「ほぞんする」ボタンでTOPに保存
- v1ではカスタムカード作成は不可（既製カードのみ）
- 検索バー（シーン名／キーワード）はv1.xで検討

### FR-004 カード確認画面（子ども実行）
- **カードは縦型に積層配置**：現在やるべきカードが画面中央〜上寄りで明瞭に表示され、その下に次のカードが**うっすら**（透過率を下げて／ピーク状に頭だけ）見えている
- メインカード構成：上半分にAI生成アニメ調イラスト、下半分にひらがなラベル
- **スワイプ（上方向）でカード操作**：完了したカードが上に消えていき、**下のカードが上にせり上がってくる**演出
- スワイプ動作と「できた！つぎへ」ボタンの両方で進められる
- 進捗ドット（現在カード・完了カード・残カードを視覚化）
- カード完了時：「できた！」表示＋軽量な達成演出（200〜400ms）
- 親モード戻り：左上の戻るボタンを長押し（500ms以上）で確認ダイアログ→TOPへ
- **タイマーなし**（カードに時間概念を持たせない）
- **実行中の編集なし**（カード追加・削除・並べ替え不可）

### FR-005 シーン完了画面
- 「ぜんぶできたね！」の達成演出（紙吹雪／キラキラ／キャラクターのアニメーション等／詳細はデザイン時確定）
- 完了したシーン名・カード枚数表示
- 「ホームにもどる」ボタン
- **スタンプ・シール等の蓄積系演出は実装しない**（その場限りの達成演出のみ）

### FR-006 オフライン動作
- TOP／カード作成／カード確認／完了の4画面はネットワーク不要で完全動作
- カードイラストは事前ダウンロード済み（無料プラン分は初回起動時にバンドル）

### FR-007 課金（フリーミアム）
- 無料：シーン3枚まで保存、プリセット3種＋既製カード基本セット利用可
- 月額480円：シーン無制限、全カードカテゴリ解放
- 月額980円：（v1では枠組みのみ。家族共有・履歴等の機能はv2）
- App Store / Google Play課金で実装
- ロック箇所からの課金導線

### FR-008 設定画面（最小）
- 子どもの名前（任意・端末ローカル保存）
- 効果音ON/OFF
- プラン状態
- プライバシーポリシー／利用規約
- 問い合わせ

## 9. 画面要件

### S1. TOP（マイシーン一覧）
| 項目 | 内容 |
|---|---|
| 役割 | 「いま使うシーン」をワンタップで取り出す入口 |
| 主要要素 | マイシーンカード（2カラム）、＋もっとつくる、設定アイコン、課金状態表示 |
| 状態 | 通常 / 編集モード（長押し起動・並べ替え・削除） / 無料プラン上限到達 |
| 遷移 | シーンタップ→S3（実行） / もっとつくる→S2 / 設定→S5 |
| 受け入れ条件 | 起動2秒以内に表示。マイシーン→実行は最短2タップ |

### S2. カード作成画面（シーン作成・編集）
| 項目 | 内容 |
|---|---|
| 役割 | 既製カードを並べてマイシーンを組み立てる |
| 主要要素 | シーン名入力、カテゴリタブ、カードグリッド（既製カード）、えらんだカード一覧（▲▼／×／プレビュー）、ほぞんする |
| 状態 | 新規作成 / 既存編集 / カテゴリ切替中 |
| 遷移 | 戻る→S1 / 保存→S1（新シーンが追加された状態） |
| 受け入れ条件 | カテゴリ選択→必要カード5枚追加→保存までを60秒以内（社内テスト基準） |

### S3. カード確認画面（子ども実行）
| 項目 | 内容 |
|---|---|
| 役割 | 子どもが自分でカードをめくり、見通しを進める |
| 主要要素 | 戻る（要長押し）、進捗ドット、メインカード（イラスト＋ラベル）、**下に控える次カードのうっすら表示**、「できた！つぎへ」ボタン |
| レイアウト | カードは縦型積層配置。現在のカードが前面、次のカードが背面に少しはみ出して見える状態 |
| 操作 | **上方向スワイプ**でカードが上に流れ、下のカードがせり上がってくる。タップでも同じ遷移が可能 |
| 状態 | 通常 / スワイプ進行中 / カード完了演出中 |
| 遷移 | 進める→次カード（せり上がりアニメ） / 最終カード完了→S4 / 戻る（長押し）→S1 |
| 受け入れ条件 | スワイプ・タップどちらでも進む。誤操作で前画面に戻らない。タイマーや時間表示は一切表示されない。次カードが「先がある」感を与える |

### S4. シーン完了画面
| 項目 | 内容 |
|---|---|
| 役割 | 達成感を子どもに刻む |
| 主要要素 | 達成アニメーション、達成メッセージ、シーン名、ホームへボタン |
| 状態 | 達成演出中（〜2秒）→ 静止 |
| 遷移 | ホーム→S1 |
| 受け入れ条件 | 演出は2秒以内に収まり、子どもがすぐホームに戻れる。スタンプ等の蓄積系UIは含まない |

### S5. 設定画面
| 項目 | 内容 |
|---|---|
| 役割 | 最小限の調整・課金状態確認 |
| 主要要素 | 子どもの名前、効果音、プラン、規約、問い合わせ |
| 遷移 | 戻る→S1 / 課金→ストア課金フロー |

## 10. データモデル

### Card（既製カード／システム提供）
```ts
{
  id: string,                // "wakeup", "brush_teeth", "wait_doctor", ...
  label: string,             // ひらがな最大8文字「おきる」
  illustrationUrl: string,   // AI生成イラストの参照
  categoryIds: string[],     // 複数カテゴリに属しうる ["morning", "everyday"]
  isPremium: boolean         // 無料プラン利用可かどうか
}
```

### Category（カテゴリ）
```ts
{
  id: string,                // "morning", "evening", "outing", "hospital", ...
  label: string,             // ひらがな「あさ」
  iconColor: string,
  order: number
}
```

### Scene（マイシーン＝ユーザーが作ったシーン）
```ts
{
  id: string,                // ユーザー固有
  name: string,              // 「あさのしたく」
  cardIds: string[],         // 並び順そのままで保持
  thumbnailCardId: string,   // 代表カード（先頭カードがデフォルト）
  isPreset: boolean,         // 初回プリセットかどうか
  createdAt: ISO8601,
  updatedAt: ISO8601
}
```

### UserProfile（端末ローカル）
```ts
{
  childName: string | null,
  soundEnabled: boolean,
  plan: "free" | "monthly_480" | "monthly_980",
  onboardingCompleted: boolean
}
```

### 永続化方針
- すべて端末ローカル（AsyncStorage）に保存
- v1ではクラウド同期なし
- 個人特定情報は子どもの名前のみ、任意
- イラスト本体は初回ダウンロード後ローカルキャッシュ

- カラーパレット：ミント（#00B894）／ブルー（#0073cc）／ソフトピンク（#FFB6B6）＋クリーム／淡ミント／淡黄の補助色
- アイソメトリック寄りの構図
- 抽象化された丸みのある子どもキャラ：2.5〜3頭身・茶色短髪・点目のみ（口は描かない）
- 背景は白 or 薄いグレー（#f6f6f6）
- 装飾はチェック・星・小さなスパークル
- 絵文字は使わない

### 採用生成ツール（固定）

**Nano Banana 2（`gemini-3-pro-image-preview`）via Google AI Studio** を唯一のルートとする。
- LP制作で既に稼働中の `shared/tools/generate_images.py` / `generate_ogp.py` を継承
- `.env` の `GEMINI_API_KEY`（[https://aistudio.google.com/apikey](https://aistudio.google.com/apikey) で取得）を使用
- Midjourney / DALL-E / Firefly への切替は**原則禁止**（ブランドトーン分断回避）
- 詳細は [`/mitooshi/skills/mitooshi-illustration-style/SKILL.md`](../skills/mitooshi-illustration-style/SKILL.md) を参照
- カード画像の格納先は `/Users/kamechi/HuX/hux/mitooshi/shared/illust/original/{label}.png`（既存31枚と同じ命名規則）

## 19. プロトタイプ作成方針（次の一歩）

### 目的
v2の体験仮説（「事前にシーンを組んでおき、子どもがカードをめくる」）が実体感として成立するかを、コードを書く前にブラウザで触って検証する。

### 形態
HTML/JS インタラクティブモック（単一ファイル、依存なし or Tailwind CDNのみ）。

### スコープ
- 検証する画面：S1（TOP）／ S2（カード作成）／ S3（カード確認）／ S4（完了）
- 検証しない：オンボーディング、設定、課金、永続化、オフライン
- データはハードコード（プリセット3シーン＋カードライブラリ20枚程度）
- イラストはダミー（手描きスケッチや暫定AI生成）でOK

### 成功条件
- 親役・子ども役の2人で触り、F2（いつもの朝）／F3（夜にシーンを作る）の体験が破綻なく流れる
- 「2タップで取り出せる」「子どもが自分でめくれる」「タイマーがなくても進む」がブラウザで体感できる
- 「カード概念」「マイシーン中心」が直感的に伝わる

### 非目標
- 本番並みのアニメーション品質
- AI生成イラストの本番アセット作成
- データ永続化、課金

### 成果物
- `/mitooshi/products/prototype/index.html`（または同等の単一ファイル）
- 触ってわかった気付きをPRD v2.1として反映
