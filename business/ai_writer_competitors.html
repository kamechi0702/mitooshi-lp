AI支援計画作成系の競合発見

前回の競合分析で完全に見落としていた領域を特定。 児発管の業務AIヘルパーとして急成長している「AI支援計画作成系」6プレイヤーを発掘し、 mitooshi Pro の戦略への影響と対応策を整理する。

※ この発見は競合分析の認識を更新します

前回の competitive_kasan_map.html では、 競合を「業務統合系（HUG等）」「個別支援計画特化（HAGONOTE）」「視覚支援系（LITALICO等）」の3カテゴリで分類していた。
今回のリサーチで、「AI支援計画作成系」という第4カテゴリが急成長していることが判明。 慶応大学発の AI-PAC、特許出願済の co-mii など、加算特化を明示した強力なプレイヤーが複数存在する。

01発見の概要

児発管の業務（個別支援計画書作成・モニタリング・アセスメント）を AI で半自動化するサービスが、 複数の事業者によって開発・提供されている。多くは令和6年報酬改定（5領域対応）に合わせて2024〜2025年に立ち上がった新興プレイヤー。

共通する特徴

  • ターゲット：児発管・職員（大人の業務AIヘルパー）
  • 機能の中心：個別支援計画書・モニタリング記録の AI 半自動作成
  • 5領域（健康・運動・認知・言語・社会性）への対応を訴求
  • 価格帯：無料 〜 月13,200円と幅広い
  • 多くが専門的支援実施加算・モニタリングを意識した設計

共通する弱点（mitooshi の差別化が守れる理由）

  • 子どもが直接触る UI を持っていない（すべて大人向けツール）
  • 子ども本人の操作データが取れない
  • 「AI が計画書を書く」ことを前面に出している → コピペ・テンプレ依存リスクを内包
  • 家庭との連続性は持っていない（toC アプリと連動しない）
  • 「行動の客観データ」ではなく「大人が入力した文言の AI 整理」が中心

重要な変化

AI 支援計画作成系の登場で、専門的支援実施加算・モニタリング・個別サポート加算Ⅰの領域は競争激化。 mitooshi の Path C（個別性の客観化ツール）は co-mii や AI-PAC との直接競合になる。
一方、集中的支援加算・家庭連携加算は依然として mitooshi の独占領域。 また「子どもが触る」「行動データ」軸は誰もカバーしていない。

05mitooshi 戦略への影響

守れる領域（変化なし）

  • 家庭連携加算（Path B）：toC × toB の連続性は誰も真似できない
  • 集中的支援加算（Path A）：3か月の行動データグラフは mitooshi 独自
  • 強度行動障害児支援加算：パニック前後の操作ログは独自
  • 「子どもが触る」体験：誰もこのクアドラントに来ていない

競合激化する領域

  • 個別サポート加算Ⅰ（Path C）：AI-PAC・co-mii・アルバトロスが押し寄せている
  • 専門的支援実施加算：co-mii が「月546単位/人」を明示訴求
  • モニタリング・個別支援計画見直し：AI 支援計画作成系が一斉に対応

新たな脅威

  • 価格圧力：デイロボ月13,200円・アルバトロス2,500〜3,500円・エデアル無料 → mitooshi Pro 月3〜5万円が割高に見える
  • 慶応大学ブランド：AI-PAC は学術背景で先生・児発管の信頼を得やすい
  • 「AI で計画書が書ける」訴求：児発管の最重要業務に直接刺さる
  • 市場期待値の変化：AI 自動化は「あって当たり前」の標準になる可能性
戦略的に重要なシグナル

これらの新興プレイヤーが2024〜2025年に集中して立ち上がっている事実は、 「療育業界の AI 化が本格化している」ことの証左。 mitooshi がこの波に乗らないと、「子どもが触るだけのツール」として周辺化するリスクがある。 逆に言えば、「子どもが触る × AI」を結び付けられれば、唯一無二のポジションを取れる。

063つの戦略オプション

Option A：完全棲み分け（純粋差別化） 保守

AI 支援計画作成系には触れず、「子どもが触る × 家庭連携 × 集中的支援」の独占領域だけで戦う。 Path B（家庭連携）と Path A（集中的支援）に絞り、Path C（個別性の客観化）は譲る。

メリット
・正面衝突なし
・開発スコープが小さい
・独自価値が明確
デメリット
・市場が狭い
・スケールに限界
・主要加算で勝負しない弱さ
Option B：補完統合（推奨） 推奨

AI 支援計画作成系と正面衝突せず、補完統合する。 mitooshi が生成する子どもの行動データを、AI-PAC や co-mii が AI で計画書化する仕組みにする。 「mitooshi が観察データ層、AI 計画作成系が記述層、HUG 等が請求層」の3層エコシステム。 パートナーアライアンス交渉も視野に。

メリット
・正面衝突なし
・AI 計画作成系の急成長に乗れる
・「データ提供層」として唯一無二
・施設は両方使う動機がある
デメリット
・パートナー依存リスク
・データ連携の API 開発が必要
・収益モデルが複雑化する可能性
Option C：直接対抗（フル統合） 挑戦

mitooshi 自身が AI 支援計画作成機能も内製し、「子どもが触る × AI 計画作成」のフル統合プロダクトとして競う。 AI-PAC・co-mii と直接対決。価格は同等または上回る。

メリット
・最大の差別化
・データの全工程を握る
・施設にとって1ツールで完結
デメリット
・開発コスト大（AI 計画作成は別ドメイン）
・競合が学術・特許で強い
・コピペ減算リスクの内包

07推奨戦略

結論：Option B（補完統合）を主軸、Option A の独占領域を初期エントリーポイント。

段階的アプローチ

  1. Phase 1（Step 1：家庭連携）： AI 支援計画作成系と競合しない領域から入る。 家庭連携加算は誰も触れていない。差別化価値の証明場面。
  2. Phase 2（Step 3：個別ボード）： 子どもが触る独自データを蓄積。 この時点で「AI-PAC や co-mii のデータソース層として連携できる」と位置付けを明確化。
  3. Phase 3（Step 4：集中的支援）： Path A（集中的支援加算）で独自価値を最大限訴求。 AI 計画作成系は集中的支援に対応していないので、ここは独占。
  4. Phase 4： AI-PAC や co-mii とのパートナーシップを模索。データ連携 API を提供して「療育エコシステムのデータ層」としての地位を確立。

営業ポジショニングの再設計

新しいセールス・ロジック

「AI で計画書を作るツールは色々ありますよね（co-mii・AI-PAC・デイロボ）。 でもその AI に渡せる『本児固有の客観データ』はどこから取りますか？ mitooshi は子どもが触ることでその客観データを生成する唯一のツールです。 AI 計画作成系と組み合わせると、本当の意味で個別性のある計画書が作れます」

避けるべきポジショニング

NG：「mitooshi も AI で計画書を作れます」と co-mii・AI-PAC と同じ土俵に立つ

慶応大学ブランド・特許出願済の競合と正面衝突するのは不利。「AI 計画作成」を主訴求にしない。

NG：「業務統合の代替」と HUG・カイポケと並列で語る

業務統合 SaaS は10,000施設導入の HUG が支配的。代替を狙うのは無謀。

08次のアクション

  1. 競合製品の実機テスト：co-mii・AI-PAC のデモ申し込み（特許文書も確認）
  2. パートナーシップ可能性の探索：ADDS（AI-PAC運営）への接触ルート調査
  3. API 連携の技術仕様検討：mitooshi のデータを AI 計画作成系にどう渡すか

本書の戦略的意味

AI 支援計画作成系の存在を見落としていたまま PRD と Discovery を進めると、Phase 2 以降で 正面衝突して敗北するリスクがあった。 早期に発見できたことで、補完統合戦略への舵切りが可能になった。 Path A（集中的支援）と Path B（家庭連携）の独占性を再確認できたことも収穫。
