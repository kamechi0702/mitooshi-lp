## 1. このドキュメントの役割

mitooshi v1(MVP) の体験仕様はすでに PRD_v3_MVP.md で固まっている。**このブリーフはその PRD をベースにデザインエージェントへ渡すための入口**として機能する。

- デザインエージェントは PRD を読み込むだけで、作るべき体験・画面・機能・制約を把握できる
- このブリーフは「PRD のどこを読むか」「どこが変更可能／不可か」「何を成果物として期待するか」をエージェントに指示する

---

## 2. 引き継ぎの切り分け（重要）

| レイヤー | 扱い | 場所 |
|---|---|---|
| **体験仕様** | **維持（変更不可）** | PRD_v3_MVP.md §1〜§11, §13〜§17 |
| **データモデル・機能要件・画面要件** | **維持（変更不可）** | PRD_v3_MVP.md §8〜§10 |
| **文言ルール・ラベル形式** | **維持（変更不可）** | content/CLAUDE.md／PRD §13 |
| **ビジュアル方針（mercari DESIGN.md ベース・#00B894）** | **刷新対象** | PRD_v3_MVP.md §12 |
| **イラストスタイルガイド** | **刷新対象** | pdm/illustration_style_guide.md |
| **プロトタイプのHTML/SVG実装** | **参考扱い（差し替え可）** | prototype/index.html |

→ デザインエージェントは **§12 と illustration_style_guide.md を新しい方針で書き換える権限** を持つ。それ以外は参照のみ・変更は別途PdM承認が必要。

## 3. 変えてはいけない体験の骨格（5画面・原則）

デザインを刷新しても、以下は保ってほしい。

### 画面構成（5画面・追加削除不可）
- **S1 TOP（マイシーン一覧）** — 事前登録シーン＋「もっとつくる」
- **S2 カード作成** — カテゴリタブ＋カードグリッド＋選択リスト＋保存
- **S3 カード確認（実行）** — **縦型積層レイアウト／上スワイプ／タイマーなし／実行中編集なし**
- **S4 シーン完了** — 達成アニメ（スタンプ不要）
- **S5 設定** — 最小限

### プロダクト原則（変更不可）
1. 2タップで取り出せる
2. カードめくりに集中する（タイマー・通知・編集など追加しない）
3. 子どもが主役（親が代行しない）
4. 見て分かる（文字よりイラスト、絵文字は使わない）
5. 2画面分離（親／子どもモード）

### ラベル規則（変更不可）
- ひらがな8文字以内
- **名詞＋動詞形式**（例：はをみがく／いすにすわる／くつをはく）

## 4. 刷新してよい領域

デザインエージェントが自由に提案・実装してよいのは以下。

- **デザイントークン**：ブランドカラー、セカンダリカラー、タイポグラフィスケール、ボタン半径、余白スケール、影の表現
- **イラストスタイル**：AI画像生成時のスタイルガイド（線画／塗り／頭身／背景／装飾）
- **キャラクター設定**：固定キャラを立てるか、都度別人物で描くか
- **達成演出の具体表現**：紙吹雪／キラキラ／キャラクターアニメ／音など
- **カードのビジュアル構造**：イラスト領域とラベル領域の配分、カード背景色の決め方
- **画面内の装飾要素**：進捗ドット・カテゴリタブ・ボタンなどの見た目
- **TOP画面のサムネイル表現**（コンポジション自由）

ただし**現行のデザイン参照ルール（mercari DESIGN.md）を差し替える場合は、同等の形式で「何をどう決めたか」が構造化されたドキュメントに置き換えること**（別ブランドDESIGN.mdに乗り換える／独自デザインシステムを定義する、どちらでも可）。

## 5. 期待する成果物

1. **新しいイラストスタイルガイド**（`illustration_style_guide.md` の置き換え）
   - 色・線・頭身・背景・装飾・プロンプトテンプレートを含む
   - image-to-image でのトーン補正ワークフローも記述

2. **デザイントークン定義**（新規作成）
   - `design/tokens.md`（または JSON）に色・タイポ・余白・角丸・影・アニメーション定数を明文化
   - React Native 実装（`theme/colors.ts` 等）にそのまま転写できる形式

3. **主要カード 5〜10 枚のサンプルイラスト**
   - 新スタイルでの実物イメージ（プリセット3シーンの代表カード推奨）
   - AI画像生成（nano banana / Midjourney 等）で出力、`/mitooshi/assets/samples/` に格納

4. **プロトタイプの刷新版** or **刷新パッチ**
   - `prototype/index_v2.html` を新規作成（または現行を更新）
   - 5画面の見た目を新デザインで再現、タップ／スワイプ／達成演出の動きも含む

5. **PRD §12 の更新差分**
   - 「イラスト・ビジュアル方針」セクションを新方針で書き換えた diff
   - PRDの改訂履歴に v2.5 として記録

## 6. 確定事項と未確定事項

### 確定（デザインエージェントは前提として扱う）
- 体験骨格（5画面）・プロダクト原則（2タップ／カードめくり／子どもが主役／見て分かる／2画面分離）
- カードラベル規則（ひらがな8文字以内・名詞＋動詞形式）
- タイマー・実行中編集・カスタムカード・スタンプ蓄積は **v1ではやらない**
- カードライブラリは 60〜80 枚（v1ローンチ時）

### 未確定（デザインエージェントが提案してよい）
- ブランドカラー（#00B894 継続か、別色採用か）
- キャラクター有無・固定化の方針
- 背景色の主軸（白／パステル／グラデーション）
- 達成演出の具体表現
- 他DESIGN.mdへの乗り換え可否（mercari以外の候補：cookpad / note / smarthr / freee 等も検討可）

### 未決事項（PRD Open Questions からデザインに関わるもの）
- Q1：カードライブラリ目標枚数（60〜80枚）の妥当性
- Q2：8カテゴリ分類の妥当性
- Q4：達成演出の具体表現
- Q8：AI画像生成スタイルガイドの確定
- Q10：プリセット3シーンの選定妥当性

## 7. デザインエージェント構成の推奨（Claude Code / Agent SDK）

PdM視点での提案。エージェント自体の構築はデザイン側で行ってよい。

### エージェントの入力
- `PRD_v3_MVP.md`（必須読み込み）
- `preset_scenes.md` / `card_library_draft.md`（カード情報）
- `content/CLAUDE.md`（文言ルール）
- このブリーフ（`DESIGN_HANDOFF.md`）

### エージェントの役割（推奨）
- **デザイントークン作成担当**：色・タイポ・余白・角丸をJSON/Markdownで定義
- **イラスト生成担当**：nano banana API を叩いてプロンプトテンプレートからカード画像を一括生成／image-to-imageでトーン補正
- **プロトタイプ更新担当**：新トークンで `prototype/index.html` を再ビルド
- **ドキュメント更新担当**：`illustration_style_guide.md` を新方針に置換、PRD §12 差分を作成

### エージェントに持たせたいスキル
- **read_prd**：PRDの該当セクションを引用して整合性を取る
- **generate_tokens**：Figma Tokens / Tailwind config / React Native theme を一括生成
- **generate_illustration**：nano banana API を叩きスタイル統一された画像を出力
- **update_prototype**：既存 HTML/SVG に変更を適用
- **dump_handoff_report**：刷新内容をPdMに報告するサマリを書き出す

### 制約ガード（必須）
- PRD §1〜§11, §13〜§17 を変更しようとしたら拒否
- カードラベルのルール（ひらがな・名詞＋動詞）を破ろうとしたら警告
- タイマー・カスタムカード・スタンプ蓄積を追加しようとしたら拒否
